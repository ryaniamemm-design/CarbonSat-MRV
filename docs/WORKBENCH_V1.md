## 1. 两个案例（来源逐字，不重新解释）

| | 案例 A | 案例 B |
| --- | --- | --- |
| 案例键 | `kubuqi_34_cells` | `engebei_paper_window_v1` |
| 数据包 | `web/npp_estimate_bundle.json`（`CarbonSat-NppEstimateBundle-v1.1`） | `web/engebei_bundle.json`（`CarbonSat-EngebeiCaseBundle-v1.2`） |
| 发布 pin | `web/npp_estimate_bundle.pin.json` | `web/engebei_bundle.pin.json` |
| 对象 | 34 个格（格心 ±`halfSpanDeg`=0.03° 方框） | 1 个研究窗口（`window.boundsWGS84`） |
| 年份 | 2001–2024（`cellYears`，816 格年） | 2001–2024（`records`，24 年） |
| 范围性质 | 数据可用性筛选出的**离散采样方框**，非治理项目边界、非治理小班边界 | **论文报告范围研究窗口**，非官方项目边界、非治理小班边界 |
| 覆盖 | 逐格逐年（部分格年为 `null`，见 §4.3） | 24/24 年一律 `PARTIAL_COVERAGE`（`validAreaRatio≈0.9312`）；数值只代表**该年有效产品足迹上**的模型 NPP 生产量 |
| 台账衔接 | 可跳转既有变化台账并**保留对象/era/年份定位** | **未接入**原 34 格台账 ⇒ 入口禁用并写明原因 |
| 核心实现 | `web/npp_entry_core.js` | `web/engebei_core.js` |

### 1.1 只读适配层
`web/workbench_core.js` **只做索引与格式化**：`buildModelA / buildModelB` 接收**已经核验通过**的数据包，
不重算 `integral → prod` 换算以外的任何科学量（该换算只是既有单位链 `kgC/yr ÷ 1000 = tC/yr` 的回归校验，见 §4.2）。
核验一律调用既有核心的 `verifyBundle(...)`，**不复制、不改写科学规则**。

### 1.2 两个核心的返回形状不同 ⇒ 必须归一化
`normalizeVerdict(v, caseKey)` 把两侧统一为
`{ok, errors, structureOk, contentOk, pinStatus, pinDetail, pinContentMatch, pinFileMatch, trustNote}`。
pin 状态按**前缀**判定（`/^MATCHED/`）：A 侧产出 `PIN_ABSENT / PIN_INVALID / MISMATCHED / CONTENT_OK_FILE_DIFFERENT / CONTENT_ONLY / MATCHED`，
B 侧产出 `MATCHED（内容 + 文件字节）` 等；**不得**用严格相等判断"已核对发布件"。

## 2. 数据与地图契约（8 条，逐条对应实现）

### C1 · 复用核心、不复制规则
所有结构/内容/关系式核验来自既有 `verifyBundle`；工作台只新增 `normalizeVerdict` 与展示层。
反例：任何把核验逻辑复制进 `workbench_core.js` 的改动都视为**违反契约**。

### C2 · 状态必须绑定案例 + 对象 + 年份 + 源产物身份；异步结果不得覆盖后来选择
单飞令牌 `createGate()`：只有**最新** token 可写入；写入前后再比对 `(caseKey, objectId, year)`。
`activate()` **每次切换都重新 fetch 并重新核验**（不缓存），因此迟到结果不会套用到新案例。
被丢弃的迟到结果计入 `STATS.staleDropped`（浏览器驱动对此有断言）。

### C3 · 面积 / 强度 / 生产量分列并带单位；空值不默认 0；合法 0 与负值保留
- 面积三分，**不可混用**：`geomAreaM2`（矢量测地）/ `gridTotalAreaM2`（栅格总）/ `gridValidAreaM2`（有效，生产量分母）。
- 生产量 `tC/yr`；原始积分 `kgC/yr`；强度 `kgC/m²/yr`；比例无量纲。
- 缺失 ⇒ `null` 并显示"—"，**绝不填 0**；`0` 与负值（MOD17 允许）**原样保留**并正常参与序列。
- 面积相等**不得**表述为像元足迹相同：`footprintIdentity` 恒为 `UNVERIFIED`。

### C4 · 几何必须可追溯
- 案例 A：`bbox = 格心 ± cellGeometry.halfSpanDeg`（数据包字段），**不手绘近似边界**。
- 案例 B：`window.boundsWGS84`（窗口规格 + 发布 pin 保护）。
- 联合 AOI 矩形（治理 32 / 对照 2）**只作分组标签**，来源
  `audit/preparatory_hardening_2026-10-16/SOURCE_ADDENDUM.md §2.1`，页面明写"不是真实治理/对照划分"。

### C5 · 可配色但必须说明口径
按**框内汇总生产量**着色，图例逐字写"框内年度汇总指标（非逐像元）"。
无逐像元数据 ⇒ **不生成连续碳量热力图**，**不绘制未取得的有效像元位置**。

### C6 · 年度序列保留 2012 分段
`eraOf(y) = y>=2012 ? 2 : 1`；序列按 era 切成两条 `<path>`，**不跨段连线**；
文案说明"2012 断点成因未证实"，**不提供**跨段差值/增幅/治理归因。

### C7 · 面积相等 ≠ 像元足迹相同
见 C3 最后一条；来源面板与明细区各有一处显式声明。

### C8 · 分享参数只承载经校验的定位
`?case=A|B&object=<id>&year=<yyyy>`；`parseShareParams` 拒绝未知案例键、非整数或越界年份、
模型载入后不存在的 `object`，以及任何多余参数。参数**不进任何摘要域**，也不承载数据/来源/核验结论。

## 4. 失败关闭（一律显式，不静默降级）

### 4.1 状态机
`idle → loading → ready | rejected`；`loading` 期间的旧结论**立即失效**（右栏清空，不显示上一案例的数值）。
`rejected` 时若保留上一份**已核验**结果，页面**必须**写明"新输入未被采用"及拒绝原因。

| 情形 | 行为 |
| --- | --- |
| 结构/关系式不符 | `rejected` + 逐条错误；**不显示**该包任何数值 |
| 内容摘要与 pin 不符（可能被改动或整体替换） | `rejected` |
| pin 缺失（HTTP 404） | 可载入，`pinStatus=PIN_ABSENT`，顶栏与来源面板均**不**声称已核对发布件 |
| pin 获取失败（网络 / 非 404 的 HTTP 错误） | 可载入，来源面板写"发布摘要未取得"并**带出具体原因**（不得写成"未提供"） |
| pin 解析失败 / 结构非法（`null`、`false`、`0`、数组、坏 JSON） | **拒绝载入**（不得静默降级成"未提供"） |
| 未知对象 / 未知年份 / 非法分享参数 | 拒绝并说明回退值 |
| 加载失败（404/网络） | `rejected` + 明确文案；核心查看仍需可用（返回案例切换） |
| 底图瓦片失败 | 按钮改「底图不可用」+ 提示；**研究框、坐标参考、年度数据仍可用** |

### 4.2 单位链回归
`prod_tC_yr = integral_kgC_yr / 1000` 在显示前逐格校验，不符即拒绝（不四舍五入掩盖）。

### 4.3 空值语义
- A：`cellYears` 缺该格该年 / 该年为 `INCOMPLETE` ⇒ `null`。
- B：`records[year]` 取数失败 ⇒ 全部栅格派生量必须为 `null`（核验器强制），页面按"—"显示。
- 序列遇 `null` 断点，不插值、不连线、不补零。

## 9. v1.1 修订段（2026-10-19）

### 9.1 P1（已修）· 历史复算证据必须绑定当前产物身份
**原缺陷**：`sourcePanel()` 的「本地源文件复算」与「上游抽样」两行**无条件** `ok:true`，
只引用历史结论、从不与当前载入的产物对照 ⇒ 换成新源/新内容并重签自摘要（甚至不带 pin）后，
旧结论仍会被继承。

**修复**：新增只读登记 `web/workbench_evidence_registry.json`
（`CarbonSat-WorkbenchEvidenceRegistry-v1.0`，构建器 `scripts/build_workbench_evidence_registry.js`，
`--freeze` 独占创建、`--verify` 重算并逐项比对且**忽略生成时间**）。登记把历史证据绑定到：

| 身份项 | 来源 | 说明 |
| --- | --- | --- |
| `caseId` + `methodVersion` | 产物自述（A 的 caseId 由适配层常量声明，数据包键集固定不含该字段） | 案例/方法身份 |
| 源产物摘要 | **构建脚本从磁盘字节独立计算**，另存包内自述值以便对照 | 只复述包内摘要**不构成**核验 |
| 内容摘要 | 既有核心重算值（A `content.recomputed` / B `stableDigestRecomputed`） | 与包内声明分开记录 |
| 数据包文件字节 + pin 文件摘要 | 磁盘字节 | 内存载入时记为"不可比"，不算不符 |
| `windowSha256`（仅 B） | 包内声明 vs 核心重算 | 窗口规格身份 |

`evaluateEvidence()` 输出四态：`APPLICABLE` / `APPLICABLE_CONTENT_ONLY`（内存载入，文件字节不可比）/
`NOT_APPLICABLE`（任一不符）/ `NO_REGISTRY`（未载入登记）。`sourcePanel()` 的 ③④ 两层据此着色，
`NOT_APPLICABLE` 时文案固定为 **"历史报告存在，未确认适用于当前产物"**（`raw=HISTORY_NOT_BOUND`），
并且**上游抽样层即便该对象年在 9 个抽样内也不得给通过色**。
上游仍只支持 `audit/upstream_spotcheck_2026-10-19/` 的 **9 个对象年**（`cell_0020` / `cell_0074` /
`engebei_paper_window_v1` × 2001/2012/2024），全量 840 = 816 + 24；未抽中者显示
"当前对象年不在已抽范围（9 / 840）"，**不得**说成已在线核验。

**正反对照（测试与独立验证均有）**：① 当前发布件 ⇒ `APPLICABLE`；② 新源 + 新内容 + 重签 + 无 pin ⇒
内部核验通过但 `NOT_APPLICABLE`；③ 保留旧源摘要、只改内容并重签 ⇒ 仅"内容摘要"不符即失效；
④ 内存载入 ⇒ `APPLICABLE_CONTENT_ONLY`；⑤ 未载入登记 ⇒ `NO_REGISTRY`，显示"未取得证据登记"。

### 9.2 P2-1（已修）· pin 载入必须区分四类状态
**原缺陷**：`pin || undefined` 与 `catch → null` 把"文件损坏/内容非法"静默降级成"未提供"，
`null` / `false` / `0` / 非法 JSON 都被当作"没有 pin"继续载入。

**修复**：`fetchBytes()` 把失败分类为 `NOT_FOUND` / `HTTP` / `NETWORK`；随后

- 404 ⇒ `ABSENT`（未钉住查看，文案"未与发布摘要比对"）；
- 网络 / 非 404 HTTP ⇒ `FETCH_FAILED`（文案"发布摘要未取得"并带出具体原因）；
- 解析失败 ⇒ **抛错拒绝载入**；
- 结构非法（`null` / 数组 / 非对象）⇒ **抛错拒绝载入**；
- 空对象 `{}` 由既有核心判 `PIN_INVALID` 并拒绝。

自动载入路径与内存导入路径（`importCase`）走**同一套**校验；浏览器驱动对四种非法输入逐一断言拒绝。

### 9.3 P2-2（已修）· 缺测表述与实测一致
**原缺陷**：文档与界面曾写"A 案例部分格年缺测"。实测：816 条 `cellYears` 中
`prod_tC_yr === null` 为 **0**、`integral_kgC_yr === null` 为 **0**、`missing === true` 为 **0**；
零有效面积的是 **23 条地类行**（`landCover[].classValidAreaM2 === 0`），其 `prod` / `intensity` 保留 `null`。

**现表述**：当前 816 个整格年均有生产量；23 条地类行无有效产品值而保留 `null`；
软件**仍支持**将来的整格缺测（`null` + 原因，**不以 0 代替**）。

### 9.4 界面升级（呈现层，不改判定）
- 主标题缩短为「CarbonSat 研究工作台」，完整产品名移入副标题；长哈希 / 生成器版本 / 测试计数收进
